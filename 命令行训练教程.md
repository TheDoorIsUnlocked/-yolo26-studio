# YOLO / RF-DETR 命令行训练教程（Ultralytics Studio 配套）

> 面向：**不走界面，直接用命令 / 脚本训练**。
> 所有命令均以 `E:\yolo\ultralytics-26_2` 为工作目录、conda 环境 `yolo` 为准。
> 实测机器：RTX 3050 Laptop **4GB**、Windows 11、torch 2.9.1+cu126、ultralytics 8.4.132、rfdetr（Apache 版）。

---

## 0. 什么时候该用命令行，什么时候用界面

| 场景                               | 界面             | **命令行**                    |
| ---------------------------------- | ---------------- | ----------------------------- |
| 边看边调参、预览结果               | ✅ 方便          | ❌                            |
| **显存紧张（≤4GB）**               | 界面本身会占显存 | ✅ **省下界面那份**           |
| 训练好几小时 / 跑一整夜            | 会锁住界面       | ✅ **后台跑，崩了不拖垮界面** |
| 一次跑多组对比实验                 | 手动重复         | ✅ **写批处理脚本**           |
| 在 C++ / 其它机器上部署同一套      | ❌               | ✅ 复制脚本即用               |
| 排查「到底是数据问题还是代码问题」 | 日志混杂         | ✅ **输出干净，好定位**       |

**一句话结论**：调参用界面，正经长训 / 显存吃紧用命令行。

## 2. 显存预算（4GB 卡必读，实测数据）

### 2.1 显存被谁吃掉了

在同一台机器上逐步实测（`nvidia-smi` 视角）：

| 步骤                                                                    | 累计占用        |
| ----------------------------------------------------------------------- | --------------- |
| **Windows 桌面基线**（Explorer / Edge / 输入法 / 豆包 / ToDesk / WPS…） | **约 1000 MB**  |
| + Python 建立 CUDA 上下文                                               | + 约 **70 MB**  |
| + 载入 YOLO 模型并推理一张 640 图                                       | + 约 **100 MB** |
| **真正留给训练的**                                                      | **约 2.8 GB**   |

**结论：界面本身只占 100~200 MB，不用为它担心；真正吃紧的是桌面那 1GB 固定开销。**
以前教程写的「界面占 1GB」是错的，已更正 —— 那 1GB 里绝大多数是 Windows 桌面。

### 2.2 训练要多少

RF-DETR Nano + 3631 数据集，在本机实测：

| 物理 batch | 梯度累积 | 等效 batch | 峰值显存    | 结论                  |
| ---------- | -------- | ---------- | ----------- | --------------------- |
| 4          | 4        | 16         | **2.47 GB** | ⚠️ 太紧，4GB 卡极易崩 |
| 2          | 8        | 16         | **1.50 GB** | ✅ 推荐               |
| auto       | 4        | 自动       | 约 1.0 GB   | ✅ 最省心             |

**核心原理**：显存峰值由**物理 batch（一次进显存的图片数）**决定；梯度累积几乎不额外吃显存。
→ **想加大等效 batch，请加梯度累积，不要加 batch。**

### 2.3 显存不够时的降级顺序

1.  `--batch` 降到 2，同时 `--grad-accum` 加倍（等效 batch 不变）
2.  关闭 EMA（RF-DETR 用 `--no-ema`）
3.  `--imgsz`（YOLO）/ `--resolution`（RF-DETR）降到 320 / 384
4.  换更小模型变体（YOLO: `n`；RF-DETR: `Nano`）
5.  关掉占 GPU 的桌面程序（浏览器硬件加速、视频软件）

## 3. 数据集准备

### 3.1 标准 Ultralytics YAML

```yaml
# 3631.yaml
path: "3631" # 数据集根（相对本 yaml 所在目录解析）
train: train/images # 也可以写 images/train，见 3.3
val: val/images

names:
  0: 3631
  1: 3631NG
```

标签为 YOLO 格式 `.txt`，每图一个同名文件：

```
<class_id> <cx> <cy> <w> <h>      # 全部归一化到 0~1
```

### 3.2 自检命令

```bash
# 看一眼数据集结构与数量（Git Bash）
echo "train 图片: $(ls 3631/train/images | wc -l)"
echo "train 标签: $(ls 3631/train/labels | wc -l)"
echo "val   图片: $(ls 3631/val/images | wc -l)"
```

> 图片数应等于标签数（没有标签的负样本图除外），数量对不上说明 label 漏了或放错目录。

### 3.3 目录布局：**两种都能跑，但有区别**

| 布局         | 结构                                      | YOLO                      | RF-DETR（用本脚本） |
| ------------ | ----------------------------------------- | ------------------------- | ------------------- |
| split-first  | `<根>/train/images` + `<根>/train/labels` | ✅                        | ✅                  |
| images-first | `<根>/images/train` + `<根>/labels/train` | ❌ **Ultralytics 找不到** | ✅ 自动适配         |

实测坑：**`3631.yaml` 里写的是 `train: images/train`，但磁盘上其实是 `train/images`。**
YOLO 官方 loader 不会自动纠正，会报：

```
RuntimeError: Dataset '3631.yaml' error  Dataset '3631.yaml' images not found,
missing path 'E:\yolo\ultralytics-26_2\3631\images\val'
```

**本教程的两个脚本都内置了自动修正**（复用 `rfdetr_adapter.py` 的双顺序探测），
会优先选磁盘上真实存在的目录，并在日志里提示：

```
· 训练集路径已自动适配：声明 'images/train' → 实际使用 train/images
[数据] E:\yolo\ultralytics-26_2\3631  （2 类：['3631', '3631NG']）
```

自动修正会在数据集根目录生成一份 **绝对路径** 的 `data.yaml`（如 `3631/data.yaml`），
**不复制图片、不改动你原始的 yaml**。不需要时用 `--no-auto-fix-data` 关掉。

> 若想一劳永逸：把自己的 yaml 改成与磁盘一致的写法即可，脚本就不需要纠正了。

## 4. YOLO 训练

### 4.1 三种调用方式（推荐第一种）

```bash
# 方式 A（推荐）：本项目的包装脚本，保证用对 python、并自动修数据路径
python train_yolo.py --data 3631.yaml --model weights/yolo26n.pt --epochs 100
```

```bash
# 方式 B：ultralytics 官方 CLI（只有 yolo 环境里装了 yolo.exe 才可用，本机在 base 环境）
yolo detect train data=3631.yaml model=yolo26n.pt epochs=100
```

```bash
# 方式 C：Python API
python -c "from ultralytics import YOLO; YOLO('yolo26n.pt').train(data='3631.yaml', epochs=100)"
```

### 4.2 `train_yolo.py` 参数全表

| 参数                 | 默认               | 说明                                                                             |
| -------------------- | ------------------ | -------------------------------------------------------------------------------- |
| `--task`             | `detect`           | detect / segment / classify / pose / obb                                         |
| `--mode`             | `train`            | train / val / predict / export                                                   |
| `--model`            | 必填               | `.pt` 权重或 `.yaml` 结构文件                                                    |
| `--data`             | None               | 数据集 YAML                                                                      |
| `--epochs`           | 100                | 训练轮数                                                                         |
| `--batch`            | 默认 16            | 物理 batch；**`-1` 自动探测**、`-0.5` 表示占 50% 显存                            |
| `--imgsz`            | 640                | 输入尺寸，**必须是 32 的倍数**                                                   |
| `--device`           | `0`                | `0` / `0,1` / `cpu`                                                              |
| `--workers`          | 0                  | Windows 保持 0；Linux 可 `8`                                                     |
| `--optimizer`        | `auto`             | auto / SGD / Adam / AdamW / RAdam                                                |
| `--lr0`              | 0.01               | **初始学习率**                                                                   |
| `--lrf`              | 0.01               | 最终 lr = lr0 × lrf（默认衰减到千分之一）                                        |
| `--weight-decay`     | 0.0005             | 权重衰减                                                                         |
| `--patience`         | 100                | 早停耐心，设 `0` 关闭                                                            |
| `--project`          | 默认 `runs/<task>` | 输出根目录                                                                       |
| `--name`             | 自动递增           | 本次运行名 `train`、`train2`…                                                    |
| `--resume`           | 关                 | 从 `last.pt` 断点续训                                                            |
| `--amp` / `--no-amp` | 开                 | 混合精度；显存不够或对精度敏感时关                                               |
| `--cache`            | False              | `ram` / `disk`，小数据集可加速                                                   |
| `--seed`             | 0                  | 随机种子                                                                         |
| `--extra`            | —                  | **透传任意 ultralytics 参数**，如 `--extra close_mosaic=0 mixup=0.1 cos_lr=True` |

Ultralytics 其它常用默认值（供 `--extra` 参考）：
`momentum=0.937`、`warmup_epochs=3.0`、`close_mosaic=10`、`mosaic=1.0`、`mixup=0.0`、
`fliplr=0.5`、`degrees=0.0`、`scale=0.5`、`translate=0.1`、`erasing=0.4`、
`nbs=64`、`val=True`、`plots=True`、`deterministic=True`。

### 4.3 本机推荐命令（4GB 卡）

```bash
# 标准配置：nano + 640 + batch 4，本机实测可行
python train_yolo.py --data 3631.yaml --model weights/yolo26n.pt \
  --epochs 200 --batch 4 --imgsz 640 --device 0

# 显存紧张时：降 imgsz / 降 batch
python train_yolo.py --data 3631.yaml --model weights/yolo26n.pt \
  --epochs 200 --batch 2 --imgsz 416 --device 0

# 最省：让 ultralytics 自己探测 batch
python train_yolo.py --data 3631.yaml --model weights/yolo26n.pt \
  --epochs 200 --batch -1 --imgsz 640
```

### 4.4 断点续训

```bash
python train_yolo.py --data 3631.yaml \
  --model runs/detect/train/weights/last.pt --resume
```

> `--resume` 会沿用那次训练的 `hyp.yaml` / `args.yaml`，**epochs 等参数由它自己恢复**，
> 命令行再传的 epochs 若小于已跑轮数会直接结束。

### 4.5 指定单卡 / 多卡

```bash
--device 0   # 第 1 张卡
--device 1   # 第 2 张卡
--device 0,1 # 两张卡（DDP）
--device cpu # 纯 CPU（调试用）
```

### 4.6 输出目录结构

```
runs/detect/train/                 # 不指定 name 时自动递增 train、train2、train3…
├── weights/
│   ├── best.pt                    # ⭐ 验证集指标最好的权重（部署用这个）
│   └── last.pt                    # 最后一轮（续训用这个）
├── results.csv                    # 每轮指标，可直接 Excel 打开
├── results.png / confusion_matrix.png / PR_curve.png / F1_curve.png
├── labels.jpg / train_batch0.jpg   # 数据增强与标注分布可视化
└── args.yaml                       # 这次训练的完整参数（复盘必看）
```

## 5. RF-DETR 训练

### 5.1 为什么不用它自带的命令

包里确实有 CLI 入口（`python -m rfdetr` / `E:\miniconda3\envs\yolo\Scripts\rfdetr.exe`），
但本机跑会直接崩：

```
ModuleNotFoundError: Requirement 'jsonargparse[signatures]>=4.27.7' not met.
  HINT: Try running `pip install -U 'jsonargparse[signatures]>=4.27.7'`
```

它是基于 LightningCLI 自动生成的，装好后参数层级很深，形如：

```bash
python -m rfdetr fit --model.model_config.xxx=... --data.train_config.xxx=...
```

**对日常训练不友好。** 所以本教程用自带的 `train_rfdetr.py`，参数扁平、可直接上手。

### 5.2 `train_rfdetr.py` 参数全表

| 参数                          | 默认            | 说明                                                     |
| ----------------------------- | --------------- | -------------------------------------------------------- |
| `--data`                      | 必填            | 数据集 YAML（两种布局均自动适配）                        |
| `--variant`                   | `nano`          | `nano` / `small` / `medium` / `base` / `large`           |
| `--resolution`                | 变体默认        | 输入分辨率，**必须是 `patch_size × num_windows` 的倍数** |
| `--resume`                    | 空              | 从 `.pth` checkpoint 继续训练                            |
| `--epochs`                    | 50              | 训练轮数                                                 |
| `--batch`                     | `auto`          | 物理 batch，`auto` 由 RF-DETR 探测显存                   |
| `--grad-accum`                | 4               | 梯度累积步数                                             |
| `--lr`                        | 1e-4            | 主学习率（见下方学习率章节）                             |
| `--lr-encoder`                | 1.5e-4          | backbone 学习率，一般不动                                |
| `--weight-decay`              | 1e-4            | 权重衰减                                                 |
| `--device`                    | `cuda`          | `cuda` / `cuda:0` / `cpu`                                |
| `--num-workers`               | 0               | Windows 保持 0；Linux 可 `4`~`8`                         |
| `--no-ema`                    | 关              | 关掉 EMA，**显存省一截，4GB 卡建议加**                   |
| `--early-stop` / `--patience` | 关 / 10         | 早停                                                     |
| `--run-test`                  | 关              | 训练结束用 test 集再评估一次                             |
| `--output`                    | `rfdetr_output` | 输出根目录                                               |
| `--run-name`                  | 自动递增        | 子目录名，留空自动 `train1`、`train2`…                   |
| `--export` / `--opset`        | 关 / 17         | 训练完自动导出 ONNX                                      |

**各变体默认分辨率**：Nano=384、Small=512、Medium=576、Base=560、Large=560。

### 5.3 本机推荐命令（4GB 卡）

```bash
# ✅ 推荐：4GB 卡最稳组合
python train_rfdetr.py --data 3631.yaml --variant nano \
  --epochs 100 --batch 2 --grad-accum 8 --no-ema

# 省事版：让 RF-DETR 自己探测显存
python train_rfdetr.py --data 3631.yaml --variant nano --epochs 100

# 完整一步到位：训练完直接导出 ONNX
python train_rfdetr.py --data 3631.yaml --variant nano --epochs 100 \
  --batch 2 --grad-accum 8 --no-ema --export --opset 17
```

### 5.4 输出目录结构

```

├── checkpoint_best_regular.pth      # ⭐ 常规权重的最佳 checkpoint（约 120 MB）
```

### 5.5 从 checkpoint 继续训练

```bash
python train_rfdetr.py --data 3631.yaml --variant nano \
  --resume rfdetr_output/train1/last.ckpt --epochs 200
```

## 7. 参数对照速查表（YOLO ↔ RF-DETR）

| 含义            | YOLO                                              | RF-DETR                                                     |
| --------------- | ------------------------------------------------- | ----------------------------------------------------------- |
| 学习率          | `--lr0`（默认 0.01，SGD）                         | `--lr`（默认 1e-4，AdamW）                                  |
| backbone 学习率 | 无（统一 lr0）                                    | `--lr-encoder`（默认 1.5e-4）                               |
| 训练轮数        | `--epochs`                                        | `--epochs`                                                  |
| 物理 batch      | `--batch`                                         | `--batch`（可 `auto`）                                      |
| 梯度累积        | 无（等效用 `nbs=64` 自动缩）                      | `--grad-accum`                                              |
| 输入尺寸        | `--imgsz`（32 的倍数）                            | `--resolution`（patch×windows 的倍数）                      |
| 权重衰减        | `--weight-decay` 5e-4                             | `--weight-decay` 1e-4                                       |
| 早停            | `--patience 100`（默认 100 很大，等于基本不早停） | `--early-stop --patience 10`（默认关闭）                    |
| 混合精度        | `--amp`（默认开）                                 | 内部自动（bf16/fp16）                                       |
| 输出目录        | `runs/detect/train`                               | `rfdetr_output/train1`                                      |
| 最佳权重        | `weights/best.pt`                                 | `checkpoint_best_total.pth` / `checkpoint_best_regular.pth` |

## 8. 常见问题排查

| 现象                                                    | 原因                                         | 解决                                                                       |
| ------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------- |
| `yolo: command not found` 或报 torch 版本不对           | `yolo.exe` 在 conda base，跑的是 torch 2.5.1 | 用本教程的 `python train_yolo.py`；或确认已 `activate yolo`                |
| `Dataset 'xxx.yaml' images not found, missing path ...` | yaml 里 `train/val` 路径与磁盘不一致         | 脚本已自动修；若用官方 CLI，请手改 yaml（见 3.3）                          |
| `Images not found` 且好几张缺 label                     | 标签目录位置不对                             | 确认 labels 与 images 同级（`train/labels`）                               |
| **训练中途闪退，日志只剩 `Unhandled Python exception`** | 显存耗尽，进程被系统直接杀掉                 | `--batch 2 --grad-accum 8`；RF-DETR 再加 `--no-ema`；关掉占 GPU 的桌面程序 |
| `CUDA out of memory`                                    | 同上但 Python 层捕获到了                     | 同上，并把 `--imgsz` / `--resolution` 降一级                               |
| loss 一直乱跳不收敛                                     | 学习率过大                                   | YOLO：lr0 降到 0.005；RF-DETR：lr 降到 5e-5                                |
| loss 几乎不动、几十轮没进展                             | 学习率过小 / 没加载预训练                    | YOLO：lr0 提到 0.02；RF-DETR：lr 提到 2e-4                                 |
| RF-DETR 下权重特别慢 / 卡住                             | 境外源，404MB 下载慢                         | 用 `python dl_weight.py nano` 预下载（带 MD5 校验），或先只用 Nano         |
| `python -m rfdetr` 报 jsonargparse 缺失                 | 官方 CLI 依赖未装                            | 不推荐修，直接用 `train_rfdetr.py`                                         |
| mAP 很高但实际检测很烂                                  | 验证集与训练集重叠 / 类别极度不平衡          | 检查 val 是否独立；看 `confusion_matrix.png` 与每类 AP                     |

```bash
# YOLO：nano + 200 轮 + 数据增强加强
python train_yolo.py --data 3631.yaml --model weights/yolo26n.pt --epochs 200 \

python train_yolo.py --task segment --data 4940_has_labled.yaml \
  --model weights/yolo26n-seg.pt --epochs 100 --batch 2

python train_rfdetr.py --data 4940_has_labled.yaml --variant small --epochs 150 \
  --batch 2 --grad-accum 8 --no-ema --early-stop --patience 20 --export
```
