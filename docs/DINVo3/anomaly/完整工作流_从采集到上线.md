# 完整工作流:从照片采集到产线上线(缺胶/毛边/黑点检测)

> 面向第一次走通全流程的操作者。两条线:**YOLO 线**(认识具体缺陷,
> 需要缺陷样本训练)和 **DINO 异常检测线**(良品建模兜底,不需要缺陷样本训练)。
> 两条线并行运行,任一触发都算 NG。

```
① 采集照片(良品为主 + 缺陷)
② YOLO 线:  ultralytics-26 训练 → best.pt → onnx → .engine ┐
③ DINO 线:  良品建库 → anomaly_bank.npz/.fbin ──────────────┤→ 放入 yolo_c++/models/
④ 绑定产品(products.conf)+ 启用(cameras.conf bank=)        ┘
⑤ 上线验证:真机跑分数 → 调阈值 → 观察 NG 触发
```

## ① 照片采集(用 yolo_c++ 自带"拍照采集")

**成像规范(先定好,之后不许随意改)**:

- 固定曝光/增益/白平衡,遮环境光,镜头光圈锁死;
- 产品定位一致(工装/托盘),拍摄角度固定;
- 黑点类小缺陷建议再加一路高分辨率局部 ROI。

**采集量**:
| 用途 | 数量 | 去处 |
|---|---|---|
| 良品(YOLO 训练+建库) | ≥300 张/产品/相机 | 训练集 + 建库 |
| 缺陷(每类:缺胶/毛边/黑点) | ≥200 张/类(YOLO 用) | 训练集 |
| 缺陷(阈值调校用) | 10~50 张/类 | 验证集 |

- 菜单里选产品、勾选相机、定时/硬触发模式,照片存
  `out/records/<产品名>/capture/cam0|cam1`(全分辨率原图);
- 缺陷样本也用同样方式采(拿缺陷品摆拍);**每张缺陷图要能在
  592×592 缩放后看清**(太小就加局部 ROI 或换镜头)。

## ② YOLO 线:训练与导出(ultralytics-26)

### 2.1 数据集准备

- 标注工具(labelimg/roboflow),YOLO 格式 txt;类别按 NG 类型分
  (如 `quejiao/maobian/heidian`),良品背景图也放一部分(约 10%)作负样本;
- 目录结构(dataset yaml 参考 `3631.yaml`):

```
datasets/<产品名>/
  images/train  images/val
  labels/train  labels/val
```

### 2.2 训练(Windows 或 Jetson 均可)

```bash
# ultralytics-26 下,改 train.py 的 data=你的yaml
yolo detect train data= model=yolo26n.pt imgsz=640 epochs=150 batch=16 < 产品名 > .yaml
# 产出 runs/detect/train/weights/best.pt
```

- 先用公开缺陷集(MVTec AD)练手也行,但正式模型必须用现场图;
- 验证:`yolo val model=best.pt data=<yaml>`,mAP50 目标 0.9+。

### 2.3 导出(**.pt → .engine 必须在 Jetson 上做**,引擎与设备绑定)

```bash
# Jetson 上(yolo26 环境),三种等价方式任选:
yolo export model=best.pt format=engine imgsz=640 half=True # 方式1
# 方式2: 先 pt→onnx,再 trtexec --onnx=best.onnx --fp16 --saveEngine=best.engine
```

产出 `best.engine`,**重命名复制到 yolo_c++/models/**,例如
`models/<产品名>_cam0.engine`。Windows 上只能到 .pt/.onnx 这一步。

## ③ DINO 线:建库(不是训练)

良品照片 → 特征库,**无需标注、无需训练**:

```bash
cd ~/ultralytics-26
# 建库(良品照片目录 = ①里采集的 cam0/cam1 目录)
python anomaly/build_bank.py --good-dir \
  models/anomaly_bank_ < 良品目录 > --out < 产品名 > _cam0.npz
# 自动同时产出 .fbin(服务端用)

# 验证(拿 10~50 张缺陷图 + 一部分建库没用的良品图)
python anomaly/validate.py \
  --bank models/anomaly_bank_ \
  --good-dir 良品验证目录 --ng-dir 缺陷验证目录 --out out/anomaly < 产品名 > _cam0.npz
```

- **AUROC ≥ 0.95** 才算有效;看 `heatmap/` 确认缺陷被红圈定位;
- 记下 summary 里的**零误报阈值**(生产起步值)和**建议阈值**;
- GUI 方式:异常检测页左侧建库、右侧验证,结果直接显示。
- 每路相机各建一个库(成像角度不同)。

## ④ 部署到 yolo_c++

文件清单(全部放 `yolo_c++/models/`):

```
models/<产品名>_cam0.engine            # YOLO 引擎(Jetson 上导出)
models/<产品名>_cam1.engine
models/anomaly_bank_<产品名>_cam0.fbin # 特征库
models/anomaly_bank_<产品名>_cam1.fbin
models/dinov3_vits16_anomaly_fp16.engine  # DINOv3 引擎(全产品共享,已部署)
```

### 4.1 YOLO 模型绑定:products.conf

```
P001 | 产品A | models/产品A_cam0.engine | 0.4 | models/产品A_cam1.engine | 0.4 | 1 | 0 | 0 | 6 | 6 | models/anomaly_bank_产品A_cam0.fbin | models/anomaly_bank_产品A_cam1.fbin
```

- 末两列 = cam0/cam1 的 DINO 特征库(留空=保持当前;`-`=该产品禁用异常检测);
- GUI"产品管理"对话框有对应输入框,切产品自动换模型+换库。

### 4.2 启用开关:cameras.conf 每行加

```
bank=models/anomaly_bank_产品A_cam0.fbin athresh=0.15
```

`bank=` 启用该路异常检测;`athresh=` 异常 NG 阈值(用 ③ 里记下的值)。

## ⑤ 上线验证

1. 重启服务(`systemctl restart hybrid-inspection`),日志确认
   `cam0 anomaly ready: bank=... (N vectors)`;
2. 界面窗格:标题栏"异常检测"勾上,参数行看**实时异常分数**——
   良品在产线上应稳定低于阈值,缺陷品放上去应超阈值;
3. 阈值调校:先设零误报阈值跑半天 → 无漏检需求高就逐步下调;
   确认帧数(`--anomaly-confirm`,默认 3)越大越抗误报;
4. 异常 NG 会触发 NG 报警输出(GPIO/Modbus,按输出设备配置),并在
   心跳里计数(`anomaly_ng`);
5. 持续把"人工确认是真缺陷但漏检"的图收进缺陷验证目录,定期复跑
   validate 调阈值。

## 常见问题

| 现象                        | 处理                                           |
| --------------------------- | ---------------------------------------------- |
| YOLO 缺陷检出但异常分数不高 | 正常,两条线互补;异常线抓的是"整体偏离"         |
| 异常分数虚高(良品也高)      | 成像与建库时不一致:查光照/曝光/位置,重建库     |
| AUROC < 0.9                 | 缺陷太小:提分辨率/加 ROI;或成像反差不足:换光源 |
| .engine 在 Jetson 加载报错  | 引擎非本机生成,用本机 trtexec/yolo export 重建 |
| 切产品后异常检测报"不一致"  | 特征库与建库骨干不同;用同一骨干重建库          |
| Windows 上 torch.hub 超时   | 脚本自动走 HF 镜像;或手动下载权重              |

## 一句话版本

**良品+缺陷照片 → ultralytics 训练 YOLO → Jetson 上转 engine;
良品照片 → 建特征库;两样都放 models/;products.conf 绑产品、
cameras.conf 加 bank= 开启 → 上线调阈值。**
